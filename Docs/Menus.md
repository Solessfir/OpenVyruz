# Menus

The menus come from `vzed\menu.cpp`. `VzMenuLoop` (`00447820`) (VzRun's loop) shows the main menu (`MenuMain` (`004271a0`)) and runs levels until the game ends; Escape during a level opens the game menu (`MenuGame` (`004223e0`), through `EngineEscape` (`00445b40`)).

## Art

`MenuLoadArt` (`00420560`) loads `Common\Data\Menu\menu.gaf` and `v-menu.gaf` (from the `tmp` copies VzRun extracts):

- `menu.gaf` animation 4 (`MENU_BG00`) is the full-screen background, drawn first at 0, 0.
- `v-menu.gaf` animation 6 (`VZfire`) is a flash over it: each update pass draws `RandomNext() % 87` and flags the flash on zero; the next draw pass draws it once and clears the flag.
- `menu.gaf` animation 8 (`cursor`, 20 frames) is the mouse cursor, drawn last at the mouse and animated only while shown.
- `v-menu.gaf` fonts: 1 for items, 2 for the item under the cursor, 4 for help texts, 5 (mode 5, alpha 0x80) for the build date `Apr 10 2000 17:52:06` that `MenuDrawBuildDate` (`00422340`) prints at 4, 464.

The flash's draws come from the shared generator. Before a level they do not matter, since `VzLoadLevel` reseeds; the game menu's draws do change the level's sequence.

## Layout

`MenuCreate` (`004209b0`) makes a menu over a rectangle with an item step: the main and game menus use 270, 90 to 640, 480 with items 45 pixels apart. Item N prints at `Left + N * StepX`, `Top + N * StepY` (the font's baseline), and the mouse is over it strictly between that baseline and the previous one, left of the rectangle's right edge. An item without text is a gap. The title prints at 10, 120 in menu font `+0x74`. The help text of the selected item prints in font 4 with word wrap inside 400, 360 to 635, 475, its cursor `LineHeight - LineGap` below the clip's top.

`RunMenu` (`00421050`) runs a menu: the cursor starts on menu `+0x4c`'s item (or where the menu's last run left it), each step runs the update pass of `MenuStep` (`00421780`), and each frame one draw pass.

## Input

PgPoll's key codes index the key name table at `0x517a94`: 1 Escape, 14 Backspace, 32 Space, 33 Return, 200 Up, 208 Down, and 0x103 the left mouse button.

- The item the mouse is over becomes the selected one (state `+0x0`), which stays when the mouse leaves; over a gap it becomes none. Only the item under the mouse prints in the highlighted font.
- Escape and Backspace choose the default item (menu `+0x5c`); Space, Return and the left button the selected one.
- Up and Down find the row under the cursor and take the one above or below; when that is the row the arrow keys last chose, or a gap, they search on in that direction for an item with text, wrapping around. The cursor then jumps to `(Right - Left + StepY) / 4 + Left`, a row's middle, and hides until the mouse moves. Whether it shows is one global (`DAT_005237a0`), not part of a menu's state, so a menu opened by a click shows the cursor at once. `RunMenu` moves the mouse to the starting item; the port never does, so a menu starts with whatever is under the pointer, and only the arrow keys move it to an item.
- The idle timeout (menu `+0x54`, 30 seconds for the main menu) returns menu `+0x58`; the main menu's 10 plays `demo.3dr`.

## Options and Extras

The Options menu (`MenuOptions`, `004229a0`) lists Video (`Details, Device, Video Mode, Gamma.`), Audio (`Music, Sound FX, Quality, Frequency, Mono/Stereo.`, or `Sound driver (DirectSound) is unavalaible.` without DirectSound), Control (`Input device, Key settings.`), User settings (`User name, Game difficulty level.`) and Language (`English.`), then Back, the default; each opens its own menu (`FUN_00422c10`, `FUN_00423e20`, `FUN_00424f30`, `FUN_00425b40`, `FUN_004259f0`).

Every one of these menus is titled Options and prints its path after the title, the last part in font 4 and the rest in font 3 (menu `+0x3c` and `+0x40`, `/Video/Details` then `/Custom`), and ends with Back, the default. The lists among them (the drivers, the custom details, the key settings, the player names) sit 50 pixels right of and 16 above the menu, items 35 apart in fonts 4 and 3. Leaving Options writes `vzconf.txt` (`ConfigSave`).

- **Video** (`FUN_00422c10`): Details Options (help `Current Graphic Details : High.` or `Low.`, from flag `0x40`), the display's driver, device and mode (`%d x %d x %d bits`), each opening a list of what DirectDraw offers, and Gamma Correction (or `Your graphic card doesn't support gamma correction.`). The port names its own display: Vulkan, the GPU and 640 x 480 x 16 bits, whose lists it does not open.
- **Gamma Correction** (`FUN_00423370`) is a slider: menu flag `+0x68` bit 0, its value (`+0x64`, 0 to 100) from the gamma's red as `(red + 255) * 100 / 510`, and its function (`FUN_004234b0`, menu `+0x6c`), which MenuStep calls each step, moves all three channels of the ramp by the change from `value * 510 / 100 - 255`. Closing it makes the ramp the user's gamma.
- **Sliders** (`FUN_004220e0`, drawn by MenuStep): `%s %d %%` with the menu's label (`+0x60`, else `Value : %d %%`) in font 1 at the menu's left and the title's height, then 100 pixels lower `[`, twenty marks `|` (the highlighted font up to the value, the item font beyond) and `]`, both fonts drawn fixed width one pixel apart. Left and Right move the value by 5 once every 150 ms while held; the left button held over the bar (from the menu's left to the window's right, 92 to 130 pixels below the menu's top) puts the value under the mouse, as a share of the bar's width.
- **Details** offers High, which sets option flags (session `+0x27e0`) `0xbe` and clears `0x40`, Low, which clears `0xae` and sets `0x40` (Translucent Panel stays as it was), either closing the menu, and Custom (`MenuVideoDetailsCustom`, `00423760`), which toggles each one as `%s : ON` or `OFF`:

| Flag | Custom item | `vzconf.txt` keyword | Effect |
|---|---|---|---|
| `2` | Shadow | `shadow` | Object shadows |
| `4` | Reactor FX | `reactor-fx` | The player's reactor glow |
| `8` | HUD Green Info | `hud-green-info` | The weapon lists, the mines note and the panel's lock and shield warnings |
| `0x10` | Translucent Panel | `translucent-panel` | The panel screen in draw mode 5 rather than 1 |
| `0x20` | TV Borders | `tv-borders` | The borders around the view |
| `0x40` | Ground/Smoke details (shown inverted) | `low-details`, or `high-details` inverted | Set, it hides `Is-detail` classes (class flag `0x100000`), the player's front light and the smoke particles |
| `0x80` | Gamma FX | `gamma-fx` | The gamma flashes and the death's red ([MainLoop.md](MainLoop.md#gamma-flashes)) |

- **Audio** (`FUN_00423e20`): Music (`FUN_00424280`: `Music : ON` or `OFF`, and Tune Music Volume while on), Sound FX, Voices (`FUN_004246b0`: each switch, its volume, and Voice type, English or Russian, `FUN_00424dc0`; switching the voices sets the help of the second item rather than the fourth), and the sound format, `Quality : %d bits` (16 or 8), `Frequency : %d Hz` (22050 or 11025) and `Channels : Stereo` or `Mono` (session `+0x1030`, `0x2a0000` from VzRun, never saved). The volumes are sliders from 0 to `0xffff` shown as 0 to 100. Quality and Frequency only change the flags; Channels reopens the sound with all three (`SoundOpen`), stopping the channels and restarting the music around it. The port reopens its output for each of the three and keeps the channels playing ([Docs/Audio.md](Docs/Audio.md#mixer)).
- **Control** (`FUN_00424f30`): Use Keyboard (relative), Use Mouse (absolute), Use JoyPad (the direction last chosen), `Direction : ABSOLUTE` or `RELATIVE` (switched only off the mouse), Key settings and Restore default settings (`Restore default key settings ?`, Yes or No, two gaps above, No the default). Its function draws the device from `menu.gaf` (animations 2, 3 and 7) at the screen's bottom left. The port plays with every device at once, so its device items do nothing, the keyboard's picture stays, and the direction switches whatever the device.
- **Key settings** (`FUN_004253f0`): the action settings of `FUN_0041de20` that the device lists (Fire, Next Weapon, Inventory, Map, Menu, Pause, High/Low Speed, Forward, Backward, Left and Right for the keyboard only, Strafe Left, Strafe Right, Panel Config), six to a page as `%s : %s` or `%s : %s + %s` (action, modifier, key) with the help `Modify setting.`, then `[Next ...]` while more follow and Back, which goes back a page. The port lists the keyboard's table, every action of which can take a key, a mouse button or a wheel notch up or down, each notch one press. Wheel up, wheel down and the fifth mouse button are the port's own codes 0x400 to 0x402, which the original reads as never down (`PgInputState`, `004695d0`) and names with nothing (`FUN_00469580`), so it prints them as `(null)`; the original's Z axis (0x102) still reads as the wheel either way. A key binds to one action only: binding it moves it there and leaves the action that had it unbound, and a key that a fixed binding holds (Help, Panel Help, the weapon digits) does not move. Choosing one shows `Waiting key or button event ...`, waits for every key and button to be up and then for one to go down (`FUN_00425860`), and binds it with no modifier, unless the binding is fixed (`FUN_0041dc90`). Escape too can be bound this way.
- **User settings** (`FUN_00425b40`): `Name : %s`, `Difficulty : %s` and Registration key (`No key.`). During a game the first two say `Cannot change this setting during the game.` Name (`FUN_004268c0`) selects a player name among the session folders (`FUN_00426cd0`), adds one (`New name : `, up to seven names) or deletes one with its sessions after asking `Delete '%s' saved sessions ?`. Difficulty (`FUN_00426fa0`) lists Easy (`For Beginners Only !!!`), Normal (`A taste of Hell.`), Hard (`Hurt me !`) and Insane (`Control Alt Del`). The port needs no registration key, so that item opens nothing.
- **Text editing** (`FUN_00425f60`): the item shows its prefix and the text, 20 characters at a time, with a caret that turns between `|` and `.` every half second; the help says `Edit your string.` until a key, then `Press ENTER to validate : ` and the text. Letters, digits and the printable characters go in; Backspace, Delete, Home, End, Left and Right edit; Return accepts a text with a letter or digit, its trailing blanks dropped, and Escape keeps the old one. The port also refuses the characters a folder name cannot hold.
- **Language** (`FUN_004259f0`): English or Russian (`Current language is %s.`, naming the language in use). `LanguageSet` (`00401000`) switches at once the value `LanguageGet` (`00401030`) returns and the key name tables, and `MenuSetLanguageStrings` (`004227c0`) retitles the menus, which are then rebuilt.

`ConfigLoad` (`0042f570`) reads `vzconf.txt`: each line a keyword, an optional `=` and a value, flags set by a non-zero `atoi`. `absolute-command` counts only before the mouse is chosen, `use-mouse` sets it, and `use-keyboard` and `use-joystick` choose the other devices. `language` and `voice-type` read `french` as the second language. `Keyboard-Settings`, `Mouse-Settings` and `Joypad-Settings` start a device's bindings, each line an action keyword (`action-fire` and on, the table at `PTR_DAT_0050d64c`) and its code and modifier. `ConfigSave` (`004303f0`) writes, in order: the header, `absolute-command`, the device's `use-` line, the audio switches and volumes, the detail flags, `gamma` (the ramp as it is), the video driver, device and mode, `use-extended-movie-player` only when the file had it, `difficulty-level`, `session-name`, `language` and `voice-type` (English or French), then for the keyboard, the mouse and the joypad in turn the header and every binding that differs from the device's defaults (`FUN_00430240`). The port reads and writes the same file, byte for byte as the original writes it, so both games share it; it reads `absolute-command` whatever the device and keeps the device and the mouse and joypad tables only to write them back; it starts from the archive's own `VZCONF.TXT`, the Max preset, for anything the file leaves out.

The Extras menu (`MenuExtras`, `00427820`) lists Scores, Credits, Intro (`Select to view intro animation.`, `Install Indeo 5.11 or higher to see the intro.` or `Intro animation file is not present.`), Slide Show only while `vz-slide.rsc` is present (`SlidesPresent`, `00404a60`), and Demo (`Auto-playing game demo.`), then a gap without the slide show, and Back, the default. Intro plays the intro ([Intro.md](Intro.md)); the port always has its decoder, so it never asks for Indeo. This executable is the Russian build: in English it still prints the Extras title, Scores, Intro and Audio in Russian (Windows-1251 strings at `0051db88`, `00513c8c`, `00513b64`, `00512828`).

- Scores shows the score table (`SaveScores`, mode 0).

## Language

This `Vyruz.exe` is the Russian build: every text it prints comes from a `LanguageGet` branch, English for language 1 and Russian, as Windows-1251 bytes, for language 2, which `vzconf.txt` still calls `French` (`language` and `voice-type`). Language 2 also reads the archive's `-fr` texts (story, credits, level pages, the ending), and voice type 2 the `french` voices and `v-intro-fr.wav`. The Cyrillic glyphs sit at their Windows-1251 codes in the Russian data's fonts, so Russian needs the Russian `vz-data.rsc`; the English data's fonts have none, and the original then prints Russian texts blank. The port stays in English over such data: the Language menu does not switch to Russian, and a `vzconf.txt` asking for it plays in English while keeping the setting. The translations are the Russian build's own, quirks kept: `English` is `Английс` and a few texts stayed English or French (`Activation Code #%d !`, `ECHAP`), as the exe holds them.

The port keeps the English texts in the code and looks each up in a table of the exe's pairs (`Source/Game/Language.cpp`), as menus draw them and where messages are formatted. Its `Format` follows the exe's printf, which tolerates a missing argument, since some Russian texts take one more.

## Scores

`SaveScores` (`0043e470`) shows the score table; with its second argument set it first enters a record for the game just ended. `EngineGameOver` is followed by it, and so are the ending pages; ending a game from the game menu is not.

- **The file:** `vz.sco` in the game folder, 0x5a0 bytes: twenty 72-byte records, best first. `ScoreRun` (`00401960`) starts a file of any other size over, empty, and writes the table back when the new record placed.
- **A record:** a 32-bit value per column (0 and 1 unused, then the tower and level of the `.3DO` `LEVEL-ID [ tower.level ]` from session `+0x26f4` and `+0x26f8`, the player's kills `+0x26c`, the money earned `+0x270`, the hit share `hits * 100 / shots`, the shots, and the game clock's hours, minutes and seconds, each modulo 60), and the player's name at `+0x34`, 20 bytes.
- **Money earned** (player `+0x270`) rises with the cash for pickups and rewards but not for spending. **Hits and misses** (session `+0x26e0`, `+0x26e4`) are counted by `AmmoHit` (`0043d7d0`) for every one of the player's shots that bursts: a hit when it struck an object that hunts the player (`ObjectHuntsPlayer` (`004371b0`), which also takes a generator of hunters) or an item, a miss otherwise.
- **Ranking** (`ScoreInsert` (`004015a0`)): the record climbs from the bottom while it is not lower on the sorted columns compared in order (tower, level, kills, money, hit share, shots), so a tie goes above the older record; the rank is 1 to 20, or 0 when it does not place.
- **The table** (`ScoreDrawLoop` (`00401670`), layout at `DAT_0050d070`): `score.gaf`'s first frame, which `FUN_00403b70` loads with its hotspot at the screen's centre (the frame is 640x480 with its hotspot in the middle), then in v-menu font 4 the headers at y 80 in `0x80ffa0` ("THE BRAVEST RESISTANCE FIGHTERS" centred 32 higher, specular `0x2000`), and rows from y 110 every 18 pixels, `#rank`, tower, level, kills, money, hit share, shots, `%02d:%02d:%02d` and the name, each aligned in its column's box (`PgFontPrintAligned` (`0044b100`)). Row colours blend from white (row 1) to `0x80a0ff` with specular `0x90` (row 20) by `ColorBlend` (`0044df60`). The new record's row is brightened in place (`ScoreHighlightRow` (`00401410`)). A key or mouse button ends it.
- Credits (`ShowCredits`, `00402990`) draws `credits.gaf`, centred on its hotspot the same way, and scrolls `credits-en.txt` (`credits-fr.txt` in the other language) in v-menu font 4 with word wrap inside 380, 0 to 639, 479, from the clip's bottom up by 0.5 pixel per step (the speed argument 500 times 0.001), until the text has passed the top or a key or mouse button goes down.
- Slide Show (`ShowSlides`, `00404aa0`) opens `vz-slide.rsc` and shows `slides\slide-001.tga` to `slide-031.tga`, each centred, for up to 4 seconds (`WaitForInput`); it starts over while any slide showed and ends on a key or mouse button. The archive holds 22 of them: eight 24-bit, thirteen 16-bit and one run-length compressed (`slide-024.tga`). The port lets the player step through them instead: the left button, Right or the wheel turned down show the next slide, the right button, Left or the wheel turned up the one before, round in both directions, and Escape ends the show; a slide left alone still moves on after 4 seconds. Extras offers the item only when the archive is there and a slide in it loads.
- Demo returns 10, as an idle main menu does, and `VzMenuLoop` plays the demo.

## Demo

`VzMenuLoop` sets the level to `cave\demo.3di` and `DemoLoad` (`004292b0`) reads `demo.3dr` (`CAVE\DEMO.3DR`): a count, then 20-byte records of the step's game-clock time, its input bits, and the player's position and direction before the step. EngineRunLevel writes no default session for it. `DemoStartPlayback` reseeds the shared generator after `LevelStartMapAnimations` has drawn and before `EngineActivateObjects`, and starts the game clock at the first record's time; steps are capped at 10 ms.

`PlayerSelectWeaponAction` (`0043bad0`) takes a recorded weapon key only when it names another slot. Only `InputReadDirection` (`0041d7e0`), the live mouse input, moves the sight (session `+0x1f9c`), so a demo neither moves nor draws it from the real mouse. The recording was made on a 60 Hz display: its record times come two to a frame, 16 or 17 ms apart, one record for each step of at most 10 ms. Played on a display of another rate, the original would run steps between records with no input, so firing and steering would drop out. The port plays the recording's own steps instead (`DemoStepLengths`, the split `--verify-game` checks), as fast as real time allows, so each step takes its record; once the records run out it goes back to 10 ms steps. The frame's draw pass, which advances animations, messages and the sight once more by the frame's last step, follows the recording too: it advances only when a recorded frame ends, by that frame's last step, so the demo keeps the pace of the 60 Hz machine rather than doing it once per frame of a faster display.

Before each step's update, unless Escape is down (which ends the demo), `DemoReplayStep` (`004291d0`) gives the record under the cursor's input once the game clock has reached its time and moves the cursor on, staying on the last record; before that the input is 0. `EngineReplayActionKeys` (`0043bb00`) then replays its actions: 0x100 the next weapon, 0x200 the speed toggle, 0x400 the map, 0x800 and 0x1000 the inventory and help flags, 0x2000 pause, 0x4000 the panel cycle (never backwards), 0x10000 << N weapon slot N + 1, and 0x8000 ends the demo. In the player's update `ReplayPlayerInput` (`00438800`) puts the player where the record before the cursor has it (`DemoReplayPosition`), with the move from its previous position in collision units as its velocity, faces it the record's way (pose 2 * direction + 1), and drives with the input, dropping the turn while strafing. The demo then returns to the menu.

## Game menu

Resume Game (the default), Options, Retry Level (only with a default session; otherwise a gap ends the list) and End Game. Retry Level asks "Retry level ?" as above and restarts from the default session; End Game asks "End this Game ?" (Yes / No, whose default is Yes) and returns to the main menu without the game-over image. A dead player's Escape ends the game at once with the game-over image.

## Sessions

`SessionWrite` (`0042ad70`) writes a session into `session\<session-name>\default` or `session\<session-name>\s%03d` in the game folder (`session-name` comes from `vzconf.txt`):

- `<zone>-<level>.3do`, the level's objects (`Level3doWrite`, `004163a0`): the banner `1.3 # File format version`, `LEVEL-NAME [%s]`, `LEVEL-ID [ %d.%d ]`, `OBJECT-COUNT [ %d ]` (the objects in the grid, not the carried ones), `3DG-FILENAME [%s]` and, with flag 8, `DIFFICULTY-LEVEL\t= %d`. Then it visits the grid from its last row and column back to the first, each cell's newest object first, the same order `EngineActivateObjects` uses; a level loaded from it therefore lists each cell's objects the other way round.
- `Level3doWriteObject` (`00416730`) writes `CREATE-OBJECT [`, `Class-name`, `Position` as `%.3f, %.3f` and only what differs from a fresh object of the class: `Name` (an object's name is its class's unless set), `Dir` (the `DirectionName` of a direction other than 0, `00407850`: `SW`, `SW_1`, `SW_2`, `S` and so on round to `W_2`), `Inertia`, `Thrust`, `Energy`, `Weight`, `Altitude`, `Shield`, `Shield-up-step`, `Life-time`, the turn timeouts, the object flags, `Reward`, `Banking-level`, `Inter-frame` and `Behaviour` (items and the like skip the facing and motion fields), then the attribute blocks (`Level3doWriteAttributes`, `00417210`): `TYPE Generator`, `TYPE Lift` and `TYPE Gate` with their state, `TYPE Key` (with `Is-Code`, `Code-Part-Id`, `Code-Part-Count` and `Code-String` for a code part), `TYPE Patrol` when it has a path, `TYPE Item` when its timeout is not zero, `ADD Ammo` for a stock the class does not have with the same count and maximum, and `TYPE Guardian` only while its location or centre is still -1, which activation fills in. Weapons are not written: the player's class carries all of them and a weapon is usable while its stock holds rounds.
- The objects an object carries (object `+0x11c`, the player's keys, code parts and surprise) are written before it, newest first, and the carrier then names each with `HAVE <name>` before its closing `]`. Flags 0xb, which every caller passes, leave out the `No-saving` classes (effects and shots) and the `HAVE` of a surprise in effect, whose object is still written.
- `last.txt` (`SessionWriteLast`, `0042b190`): `#0 1`, the session folder (`session\<name>\s%03d`), the zone, the `.3di` file, the level name, then one number a line: the game clock in milliseconds, the player's energy and shield (`%.3f`), the weapon slot in hand, the difficulty, the shots that hit and that missed, the kills, the money earned and the cash.
- For a numbered session, `<zone>-<level>.tga` (`SessionWriteThumbnail`, `0042b360`): the screen shrunk to 224x168, an uncompressed 16-bit Targa from the bottom row up, which the session menu shows at 8, 150 for the session under the cursor.

Every file the original writes, these and `vzconf.txt`, first has its old copy renamed to `<name>.bak` (`FileBackUp`, `00404850`). A numbered session takes the highest number in the folder plus one, from `s000`, and the sessions seven or more numbers below it are deleted. EngineRunLevel writes the default session as a level starts, unless the level came from a session; `ObjectUpdateLevelExit` writes it too. The default folder keeps every level's `.3do` it has been given.

`SessionLoad` (`0042ba00`) reads `last.txt` and loads the level with the session's `.3do` in place of its own (`LevelLoad3do`, `00413d80`), which also sets the difficulty. A `HAVE <name>` inside `CREATE-OBJECT` takes the named object off the level and gives it to the object being read (`Level3doTakeNamedObject`, `004160a0`, which searches the grid from its last cell back, each cell's newest first, and matches the name exactly); a number after the name sets that item's timeout. An `ADD Ammo` block sets the stock of the same ammo, or adds one. The player is the last `Player` object `EngineActivateObjects` activates (`EngineActivateObject`, `0043c150`), the one in the lowest cell and the oldest there; since a reload reverses each cell's order, a level with two players in one cell (`HITEK\T1H1`) swaps them on each reload.

A `Saving-Plot-Area` object (`Saving-zone`, invisible, 64 pixels) and a `Saving-Plot` object (`Saving-plot`, `Reward = -100000`, the cost) lie at the same position. While the living player touches the area, `EngineUpdateObjects` finds the plot in the area's cell at exactly the same position and calls `SavingPlotUpdate` (`0042a3b0`), timed on PgClockNow:

- The first contact starts the count and clears the done flag.
- Before 5.5 seconds it shows `Saving in %d second%s` with `(6000 - elapsed) / 1000` seconds, the `s` only above one.
- Then, once: without the cash, `Not enough Cash %s !\n You need %d $\n  to save this game ...` with the player's name, for 5 seconds; otherwise the cost comes off the cash, `SessionWrite` writes a numbered session, and `Saving Completed.` shows for 3 seconds.

The texts print at the plot minus 150, 50 in world space in `v-bonus.gaf` font 6, each replacing the last. Once the player touches no area, `SavingPlotLeave` (`0042a650`) ends the count; before the save or refusal it removes the message at the plot's x - 150, y (not y - 50) and shows `No Saving.` for a second. `SessionLoad` (`0042ba00`) in mode 0 sets the counting flag without restarting the count, so the plot a saved session starts on does not save again until the player leaves it.

`SessionChoose` (`00427c30`) lists up to seven sessions over 265, 70 with items 35 pixels apart, title `Saved sessions`, fonts 4 and 3, each as `%s   [%d h %d mn %d sec] ` with the help `Energy : %d\nShield : %d\nDifficulty : %s ...\n`, then a gap when there are fewer than seven, and `Back`, the default. The cursor starts at the screen's middle.

## Port

`Source/Game/Menu` draws and steps a menu; `Source/Main.cpp` runs the main menu, the game menu, the questions, the session menu, Options and its menus, Extras, the credits and the slide show. `Source/Game/Input` holds the action bindings, their codes and names. The menus print English throughout. `--level` and `--start` skip the main menu at startup.

`Source/Game/Session` reads and writes the original's own sessions in the game folder's `session\<session-name>`, so the port and the original share one save folder; `vz.sco` sits beside it in the game folder too. The port writes what it keeps of each object: the class, the position, the facing, the energy and shield of a body, the gates' and lifts' state and the other attribute blocks as the level gave them, and for the player its stocks, its carried keys and surprise and `last.txt`. It also writes the state the original keeps on top of the class: a body's velocity (`Inertia`, object `+0x140`), and for the player and actors the speed (`Thrust`, `+0x198`), the turn timeout (`+0xec`, which the speed toggle slows), a heli's tilt (`Banking-level`, `+0x21c`) and the body pose turning toward its target (`Inter-frame`, `+0x230` and `+0x234`); the `Invisible` and `Only-base` flags (object `+0x128` bits 8 and `0x20`), and for a wreck its `Behaviour` (`Fixed `, as `FUN_004161e0` names it) and its shield step, which the first death zeroes. Loading gives them back, the pose only when both numbers are set and the top's pose from the same pair, as `LevelLoad3do` does; high speed still returns the player to the class's turn timeout, and `Speed-max`, which the original does not write, starts at the class's. It leaves out `Life-time` (`+0x120`), the age the original adds each step only while an object is in its update list (actors age with the clock, pushed scenery by its steps in motion), since the port does not keep that list and nothing it runs reads a saved object's age, and `Turret-turn-timeout` and the other flags, which the port never changes. Loading goes through the level loader with the session's `.3do`, then takes the carried objects off the level as the player's keys and surprise and sets the clock, the weapon slot, the cash, the money earned, the kills and the shot counts from `last.txt`. The thumbnail is the frame drawn just after the save, so it shows `Saving Completed.`, where the original's shows the frame before. `--verify-game` checks that every level written as a session and loaded back writes the same objects, with removed objects, one created during play, changed doors, a changed stock, a carried key, an actor in motion, mid-turn, tilted and turning slower, a pushed body, a wreck and a moving player, that `last.txt` reads back, and that a saving plot saves once, for its cost, after 5.5 seconds. Both games load each other's sessions: the original reloaded a session the port wrote and saved the same objects again.

## In-game actions

`EngineReadActionKeys` (`0043b5c0`) reads the action keys each update, by the ids of the table at `PTR_DAT_0050d64c`: 1 fire, 2 to 5 forward, backward, left and right, 6 and 7 the strafes, 8 next weapon, 9 `action-toggle-hilo-speed`, 0xa map, 0xb inventory, 0xc help, 0xd pause, 0xe cycle panels, 0xf menu, 0x10 to 0x18 the weapon slots and 0x19 `action-pannel-help`. `InputActionDown` (`0041d650`) finds an action down when its modifier, if any, and its code are down, through the device's table: the keyboard's (`DAT_0052346c` and `DAT_00523378`, defaults `DAT_00509298` and `DAT_00509300` from `InputSetDefaultKeys`, `0041d420`), the mouse's (`DAT_00523000` and `DAT_005233e0`, defaults `DAT_00509368` and `DAT_005093d0`) or the joypad's (`DAT_00522c6c` and `DAT_005234d4`, defaults `DAT_00509438` and `DAT_005094a0`). Bit 31 marks a fixed binding. The codes are PgPoll's (the names at `00517a94`, entry code - 1): 1 Escape, 2 to 0xb the keypad digits, 0xe Backspace, 0xf Tab, 0x10 to 0x1b F1 to F12, 0x1e Left Shift, 0x20 Space, 0x21 Return, 0x30 to 0x39 the digits, 0x41 to 0x5a the letters, 0xc7 to 0xd3 the cursor block (0xc8 Up, 0xcb Left, 0xcd Right, 0xd0 Down, 0xd1 Page Down); 0x100 + n is the mouse's input n (0x103 to 0x106 its buttons) and 0x200 and up the joypad's.

The keyboard's defaults: Space fires, Up, Down, Left and Right move, Left Shift with Left or Right strafes, Backspace takes the next weapon, Page Down toggles the speed, M the map, I the inventory, P pauses, Tab cycles the panels, Escape opens the menu, and fixed ones: F1 help, F2 panel help and 1 to 9 the weapon slots. The mouse's: the left button fires, the right one thrusts, Down backs off, Left and Right strafe, and left and right turning have no binding; the rest as the keyboard's. The joypad's: button 4 fires, its stick moves (fixed), button 5 with the stick strafes, buttons 6 and 7 take the next weapon and toggle the speed.

- **Speed toggle** (Page Down, `FUN_0043b830`): with the player's `Speed-max` (object `+0x1a4`, class `+0x64`) at the class's or more, it drops to a third of the class's (`DAT_005095dc`) and its turn timeout (object `+0xec`) grows by half (`DAT_005095d8`), saying "low speed"; otherwise both return to the class's values and it says "high speed". `Speed-max` bounds when thrust pushes (a tenth of it), so low speed lowers the top speed, not the acceleration. The panel then shows the boost light (Weapons4) since it differs from the class's. It is ignored while the player's `+0xd4` is 7.
- **Help** (F1) sets session `+0x20d0` bit `0x400` and says "help"; **inventory** (I) sets bit `0x200` and says "inventory" (held 2 seconds rather than 5); **panel help** (F2) toggles bit `0x800` and says "help" as it turns on ([Hud.md](Hud.md#panel-help)). A demo's records can set the first two (bits `0x1000` and `0x800` of `EngineReplayActionKeys`, `0043bb00`), but `DEMO.3DR` never does. `InputActionPressed` (`0041d4c0`) is an edge: the action down in PgPoll's current key states (`DAT_00526d90[0]`) and not in the previous poll's (`[1]`, `FUN_0041d710`).

## Inventory and help

The frame that sets bit `0x200` or `0x400` skips the messages' draw pass (`FUN_004315f0`); the next one runs the inventory (`FUN_00439b00`) or, without it, the help (`FUN_0043ab50`) in place of the frame, in a loop of its own until its bit clears. Both keep the last frame shown (`FUN_0044f6d0` copies the front buffer to the back) and work the same way:

- **Window** (`FUN_00439ec0`, `FUN_0043aef0`): `Common\Data\Menu\v-inventory.gaf`'s first animation, loaded twice as the level starts (`FUN_00439a20` at session `+0x2608`, `FUN_0043b3d0` at `+0x2654`), has one 64x64 frame. The window is as many whole tiles as fit with one to spare, centred: 576x384 at 32, 48 on a 640x480 screen, 9 rows of 40 pixels. `FUN_0043a980` draws the tiles once in draw mode 13, whose specular `0xc8c8c8` (`DAT_00516fd0`) darkens what lies under each opaque pixel to 0x37/0xff, then the edges in mode 10, adding blue 100 (`DAT_00516fd4`) along the top and left and 50 along the bottom and right, and keeps the result; each frame copies it back and draws the rows over it.
- **Rows**: from 32, 40 inside the window, each 40 pixels below the last, an icon 8 pixels down and the text 50 pixels in, in v-inventory's font 1 forced to draw mode 7. Rows past the window's last are laid out but not drawn. The update pass plays the icons of the rows below the scroll, by the step.
- **Keys** (`FUN_0043a8a0`, `FUN_0043b2f0`): 100 ms after opening, then 100 ms after each key that did something, every step: Escape, Space or Return held, or the screen's action pressed again, closes it; Up or Down held scrolls a row, down while the scroll is below what the list returned less the window's rows. The inventory counts its timer down by the time still to step, the help by the step. The frame that closes still shows the empty window. Meanwhile only the voice queue (`VoiceQueueUpdate`) runs, so the game's time stands still.
- **Arrows**: v-bonus.gaf's animations 2 and 3, played by the step, at 16 pixels in from the window's right and from its top while scrolled, and from its bottom while more rows lie below.

The inventory (`FUN_00439f90`) lists, each list only while the window has rows left and each but the last followed by an empty row:

1. **Codes** (`FUN_0043a120`): each code the player carries a part of, newest first, as `Code #%d : ` and its parts' `Code-String`s joined by `-`, `???` for a part not carried, with the newest part's item as the icon. Only the rows below the scroll count.
2. **Keys** (`FUN_0043a540`): each carried key that is not a code part, `Key #%d` (Russian `Ключ #%d`). Every key counts.
3. **Weapons** (`FUN_0043a6e0`): the slots from the first with rounds, round through `FUN_004376a0` to it again, each counted; a slot with a bound stock shows the panel's icon and `%s (%d/%d)`, the weapon class's name with the stock's count and maximum. Binding each slot in turn (`FUN_004375f0`) clears every weapon's last shot, the one in hand's too, so it fires at once after the screen.

The help (`FUN_0043b0f0`) lists every action of `FUN_0041de20`'s full table that the device binds, as `%s : %s %s` (name, `key`, the key's name) or, with a modifier, `%s : %ss %s %s %s` (name, `key` and an s, the modifier, `and`, the key); in Russian `жмите` and `и`, with the same s. The table runs Help, Panel Help, Weapon #1 to #9 (keyboard only, with the slot's panel icon), then the key settings' entries; Menu and Pause stay English in both languages.

The original, checked in `cave\t1c2` with the first part of code 3, shows `Code #3 : ACTIVATE-???-???` and `Gatling-II (1000/5000)`, which `--verify-game` checks along with the help's first rows and v-inventory's font. The port captures the frame that opened a screen before its gamma and runs the screen as the original does; the darkening and the edges match the original's.

Not ported yet: the original's joypad device (the port reads its own pad layout, [PlayerMovement.md](PlayerMovement.md#gamepad)), the score row's own brightening (the port draws its text twice, additively), the demo's pause, the exit explosions (`MenuExplode`, `00421460`: up to 400 random Explosion and Small-Explosion animations over the menu for at most 10 seconds, only while a level's classes are loaded), and the "Licensed to" line.
